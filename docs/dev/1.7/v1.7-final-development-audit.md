# v1.7 开发收口深度审查报告

**日期**: 2026-06-13  
**审查依据**: v1.6 功能审查、v1.7 SDD、v1.7 开发计划、当前代码与测试  
**审查维度**: 开发意图、功能逻辑、代码实现、边界处理、测试与文档一致性

## 1. 总体结论

v1.7 当前实现已经覆盖 v1.6 功能审查提出的六个核心缺口，并且实现路径符合“不推翻 v1.6 基础闭环、在现有链路上补齐精炼/隔离/解释能力”的开发意图。

逐项判断：

| 缺口 | 当前状态 | 结论 |
|---|---|---|
| G1 raw_chunk 不是精炼记忆 | `reflection/extraction.py` 提供 typed candidates，raw chunk 保留为 episode 审计层 | 已有基础补强 |
| G2 heuristic 提取偏窄 | decision / todo / preference / policy / correction / procedure 等候选已有测试覆盖 | 已有基础补强 |
| G3 scope 未贯穿反思写入 | hooks、manual reflect、reflection reads/writes、compaction、curator 都传递同一 scope helper | 已完成主链路 |
| G4 graph 非 typed KG | `core/graph.py` 新增 typed fact sidecar，与 Hebbian co-activation graph 分层 | 已完成轻量 sidecar |
| G5 supersedes 不够语义化 | `reflection/supersedes_resolver.py` 独立 `store/merge/supersede/skip/scope_split` 裁决 | 已完成起步闭环 |
| G6 compaction fallback 弱 | scored fallback、token accounting、LLM quality gate 已接入 `_compact_episode_zone()` | 已完成质量补强 |

剩余不是“功能没做”，而是后续增强方向：relation-aware recall、fact-level temporal query、更完整的 tool observation summarizer 和更强的 LLM batch resolver。

## 2. 审查发现与修复

### F1. compaction LLM helper 存在历史 fallback 残影

**现象**: `_llm_summarize_cluster()` 内部保留了 `fallback = max(bodies, key=len)` 的旧变量，但当前设计已经改为外层 `_compact_episode_zone()` 统一执行 scored fallback 和 quality gate。

**根因判断**: 代码实现演进后遗留的局部残影，不是功能意图问题。它不会改变运行结果，但会误导维护者以为 LLM helper 自己仍承担 fallback 责任。

**修复**: 删除未使用 fallback 变量，保持职责边界清晰：LLM helper 只返回 LLM 文本或 `None`，fallback/quality gate 只在 caller 中执行。

### F2. scoped compaction 测试未验证“其他 scope 原始 episode 不被 supersede”

**现象**: 原测试只断言生成的 compacted summary 属于 `u1`，没有直接断言 `u2` raw episode 仍保持 active。

**根因判断**: 边界测试不够硬，属于测试覆盖缺口。代码主路径已经通过 `list_by_zone(..., filters=scope_filters)` 做 scope 读取，但验收证据没有完整覆盖误 supersede 风险。

**修复**: 在 `tests/test_reflection_scope.py::test_compact_episode_zone_respects_scope_filters` 中记录 `u2` episode ids，并断言 compaction 后它们全部 `not temp_store.is_superseded(id)`。

### F3. 1.7 文档状态仍停留在“in progress/下一步”

**现象**: `docs/CHANGELOG.md` 和 `docs/dev/1.7/v1.7-development-plan.md` 中 Phase F 仍未完整反映全量测试、coverage 同步、Windows basetemp 隔离和 recovery callback 兼容修复。

**根因判断**: 代码和测试已经推进，但文档状态没有同步更新，属于发布记录滞后，不是程序框架问题。

**修复**: 更新 changelog Phase F 与 v1.7 开发计划当前状态，明确 `615 passed`、coverage index sync、scoped compaction boundary、Windows test isolation 和 recovery callback compatibility。

## 3. 未发现需要立即修复的问题

- scope helper 的当前设计保留了 local-global 兼容模式；这与 v1.7 SDD 的 compatibility 目标一致，不应改成 mem0 式“必须至少一个 scope id”的硬约束。
- typed fact sidecar 作为轻量 sidecar 存在，不覆盖原 Hebbian graph；这与 v1.6 审查中“不要混用共同出现边和事实关系边”的根因判断一致。
- semantic resolver 当前是启发式起步闭环，不是完整 LLM batch dedup；这符合 v1.7 增量交付目标，后续可增强但不属于当前 release blocker。
- compaction quality gate 采用保守拒绝策略。当前测试覆盖 verbose/noisy LLM fallback；后续可继续调低误拒风险，但当前策略更符合“不要把噪声写入长期记忆”的发布目标。

# v1.7 开发计划与参考实现索引

**日期**: 2026-06-12  
**基线**: v1.6 功能审查 + 深度根因审查 + 当前主线代码  
**目标**: 把反思链路的 scope 贯穿、提炼质量和图谱语义分阶段补齐

## 1. 当前判断

v1.6 已经把“能存、能搜、能维护”跑通，但从开发者视角看，根因不是某个函数单点写错，而是横切能力没有被抽成稳定抽象。  
所以 v1.7 的推进方式应该是：

1. 先把 scope context 作为一等输入贯穿 reflection / compaction / curator / tool entrypoints
2. 再把 raw transcript 提炼成更稳的事实记忆
3. 再决定 supersedes / merge 的语义化判定
4. 最后才考虑 typed graph 和更强的 compaction 质量

## 2. 已完成的 v1.7 起步项

- `core/scope.py` 新增 `scope_from_context()`
- `runtime/hooks.py` 已开始把 scope 传给 context assembly、micro/full reflection、compaction、curator
- `reflection/runtime.py` 已开始在反思和 compaction 写入时 stamp scope fields
- `runtime/schemas.py` / `runtime/tools.py` / `runtime/registration.py` 已给 `srh_reflect_now` 补上 filters 支持
- `reflection/extraction.py` 已抽成共享提炼层，并开始输出 `kind` / `priority` 结构化候选
- 文档版本已切到 v1.7

## 3. 分阶段开发计划

### Phase A: Scope Context Propagation

核心任务：

- 保证 `pre_llm_call`、`on_session_end`、`srh_reflect_now` 都能携带 scope
- 保证 `reflection/runtime.py` 写出的新 memory 继承 scope metadata
- 保证 `compact_episode_zone` 只处理当前 scope 的 episode

优先测试：

- hooks 传参测试
- full reflection 读写 scope 测试
- raw chunk reflection scope 测试
- compaction scope 测试

### Phase B: Refined Fact Extraction

核心任务：

- 将 raw chunk 保留为审计层
- 增加事实 / 偏好 / 决策 / 待办的类型化抽取
- 让 heuristic path 先做质量门，再做分段提炼

当前状态：

- 共享提炼层已落地
- 决策 / 待办 / 偏好 / 显式意图已经在候选层被区分
- 后续可继续把 procedure / skill seed 路径接到更强的提炼策略里

### Phase C: Semantic Supersedes

核心任务：

- 让替代关系支持“局部替代”与“并存但不同 scope”
- 结合候选召回 + 批量语义判定，减少误替代
- 把 supersedes 从结构字段升级为有判断依据的维护动作

当前状态：

- `reflection/supersedes_resolver.py` 已把 `store / merge / supersede / skip / scope_split` 的语义裁决独立出来
- embedding 路径的微反思已不再把 generic memory intent 直接提升为 supersedes
- full reflection 的 LLM 路径也已接入同一 resolver，generic intent 会保留为普通记忆而不是盲目写入替代链
- `MemoryStore.put()` 已开始拒绝跨 scope 的 supersedes 目标
- 后续还需要把 full reflection 的批量判定和 typed graph invalidation 继续接上

### Phase D: Typed Fact Graph Sidecar

核心任务：

- 保留现有 co-activation graph
- 新增轻量 typed fact sidecar，记录 self-contained facts / relations
- 为 episodic source、entity、invalidation 提供可追踪边

当前状态：

- `core/graph.py` 已新增 typed fact sidecar 表与 `record_typed_fact()` / `typed_facts()` / `invalidate_typed_fact()` 接口
- reflection 写入和 graph distill 已开始向 sidecar 写入 relation / source / target / invalidation 轨迹
- entity mention 现在会通过 `record_entity_mentions()` 写入 sidecar
- `remove_memory()` 已开始对相关 typed facts 做失效标记，避免悬挂关系

### Phase E: Compaction Quality

核心任务：

- 升级 fallback 逻辑，避免最长文本误导摘要
- 增加 token accounting 和摘要质量门
- 让 compaction 输出更接近“可读的结论”，而不是“压缩后的噪声”

当前状态：

- `_compact_episode_zone()` 和 `_llm_summarize_cluster()` 已切到共享 scored fallback
- fallback 会优先选择 conclusion-like 片段，并过滤掉“没有结论”的旁白型噪声
- compaction 结果现在会返回 source/summary token 统计和 compression ratio
- verbose LLM 输出会先过质量门，低于 fallback 的会自动回退
- `tests/test_compaction.py` 已补上代表性结论、token accounting 和 noisy LLM 回归

### Phase F: Hardening

核心任务：

- 回填测试缺口
- 同步 docs / changelog / coverage
- 复核跨模块兼容性

当前状态：

- `pytest tests --collect-only -q` 已刷新到 **615 collected tests**
- `docs/testing/test-coverage.md` 已同步当前测试面与 compaction 细节
- Windows pytest `basetemp` 已改为 per-run 隔离，避免 stale temp ACL 干扰全量套件
- runtime recovery/import-hygiene 测试已对齐当前 scoped recovery callback 签名
- scoped compaction 测试已补充跨 scope raw episode 不被误 supersede 的边界断言
- 当前全量验收基线：`pytest tests -q` -> **615 passed**

## 5. 实施顺序建议

1. 先完成 Phase A 的 code + tests + docs
2. 再做 Phase B 的提炼质量提升
3. 然后再碰 Phase C 的 supersedes 语义
4. Phase D / E 只在前面两阶段稳定后推进

## 6. 当前风险提醒

- 不要把 typed graph 直接塞进现有 Hebbian graph 表里
- 不要为了让 reflection “看起来更聪明”而放松 scope 约束
- 不要一次改动反思、curator、dashboard 和 graph 四条主线

# v1.7 软件开发设计文档 (SDD)

**版本**: v1.7  
**日期**: 2026-06-12  
**基线**: mem-reflection-hermes v1.6 latest + scope-aware reflection phase A  
**方法论**: 先分阶段收口缺口，再做局部验证与回归

## 1. 目的

v1.6 已经把记忆存储、事件账本、作用域过滤和 curator 主干跑通，但反思链路仍然存在“scope 在存储/检索层有了，反思写入和压缩层没有完全继承”的横切缺口。  
v1.7 的目标不是重写整个记忆系统，而是把现有闭环从“可运行”推进到“可提炼、可隔离、可解释”。

## 2. 问题定义

### G1 默认 `raw_chunk` 更像存证，不是精炼记忆

原始会话切块可以保留审计，但不能替代长期事实、偏好、决策和待办的稳定抽取。

### G2 启发式提取偏窄

当前 heuristic 主要抓显式意图、纠正和偏好，对隐含结论、协作约定和多轮收敛不够敏感。

### G3 scope 没有贯穿反思写入

`user_id` / `agent_id` / `run_id` 已经存在，但反思、压缩、手工触发 reflection 入口还在部分路径上默认走全局读写。

### G4 graph 仍是 co-activation，不是 typed knowledge graph

现有 graph 适合联想召回，不适合事实关系、无效化和时序真值。

### G5 supersedes 判定仍然偏结构

替代关系更多依赖显式标记与相似度，语义层面的“是否应替代”还不够稳。

### G6 compaction fallback 仍弱

无 LLM 时的压缩如果只是截断或最长片段选择，会留下噪声而不是结论。

## 3. 设计目标

| 目标 | 描述 |
|---|---|
| **Scope first** | 反思读写、压缩、工具入口都先继承 scope，再谈抽取质量 |
| **Refined memory** | raw transcript 只做审计层，长期层输出更高质量的事实/决策/偏好 |
| **Compatibility** | 单用户、本地无 scope 模式保持原有全局行为 |
| **Traceability** | 每条 refines / supersedes / compaction 都能追溯来源 |
| **Incremental delivery** | 每个 phase 都能独立验证，不要求一次把图谱重写完 |

## 4. 非目标

| 非目标 | 原因 |
|---|---|
| 分布式存储或 remote vector 后端 | 不是当前插件的必要路径 |
| 一次性把 Hebbian graph 改造成完整 KG | 这属于独立架构轨道 |
| 引入新的外部服务依赖 | 先把 SQLite-native 方案做稳 |

## 5. 分阶段方案

### Phase A: Scope Context Propagation

目标：把 scope 作为反思链路的一等输入。

范围：

- `pre_llm_call` / `on_session_end` 解析并传递 scope
- micro / full / raw reflection 写入时填充 `user_id` / `agent_id` / `run_id`
- compaction 只处理当前 scope 的 episode
- `srh_reflect_now` 支持可选 `filters`

验收：

- scoped 会话写出的反思记忆不再落成全局默认值
- scoped compaction 只压缩当前 scope 的 episode
- 旧的单用户无 scope 模式行为不变

### Phase B: Refined Fact Extraction

目标：让反思结果从 raw chunk 提升为事实、偏好、决策、待办的类型化提炼。

### Phase C: Semantic Supersedes

目标：把替代判断从“结构上有 supersedes”推进到“语义上适合替代”。

### Phase D: Typed Fact Sidecar Graph

目标：保留现有 co-activation graph，同时新增轻量 typed fact sidecar。

### Phase E: Compaction Quality

目标：把 fallback 摘要从“最长文本”升级为“最能代表结论的片段 + 保守合并”。

### Phase F: Hardening

目标：补足测试、文档和回归约束，稳定发布。

## 6. 受影响模块

| 模块 | 预计变化 |
|---|---|
| `core/scope.py` | scope 归一与 context helper |
| `reflection/runtime.py` | scope-aware reflection writes / compaction |
| `reflection/engine.py` | 兼容层签名扩展 |
| `runtime/hooks.py` | scope 传递与 context 组装 |
| `runtime/tools.py` | `srh_reflect_now` filters 透传 |
| `runtime/schemas.py` | reflect-now schema 增加 filters |
| `memory/curator/` | curator scope helper 对齐 |
| `docs/*` | 版本和工具说明同步到 v1.7 |

## 7. 验收标准

- 反思写入的 frontmatter 会继承当前 scope
- compaction、curator、context assembly 都会尊重同一套 scope helper
- `srh_reflect_now` 在手工触发时也能保持 scope 安全
- 新测试覆盖 hooks、reflection、compaction 的 scope 传播

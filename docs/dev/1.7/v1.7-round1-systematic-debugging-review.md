**日期**: 2026-06-13

**基线**: plugin.yaml version = 1.7，测试 615 条全部通过，文档已对齐

## 执行摘要

v1.7 的功能实现（scope propagation、refined extraction、semantic supersedes、typed fact sidecar、compaction quality）在测试层面已闭合，但系统调试审查发现 **15 项潜在问题**，集中在四个跨领域主题：

1. **仪表盘 `web/api.py` 的导入路径与错误处理漂移** — 生产路径可能降级为无图状态，而测试因 mock 环境无法发现。
2. **静默失败/降级模式过度使用 `logger.debug`** — 导致关键子系统（typed sidecar、graph、bridge）在运行时被忽略。
3. **scope filter 在部分边界条件下语义不一致或丢失信号** — 尤其体现在 curator 与 search rerank 的加权模式下。
4. **graph 与 store 的耦合依赖内部属性约定** — `_graph` 属性不存在时，typed fact sidecar 等功能被静默跳过。

本轮报告 **只记录、不修复**，为第二轮根因深挖提供锚点。

## 跨领域主题聚合

### 主题 1：仪表盘与运行时图服务的接口漂移
- **代表问题**: L1-1, L2-5, L5-12（graph 相关分支）
- **根因假设**: v0.9.2 的 dashboard 直接构造 `GraphManagerCompat(plugin_data_dir() / "graph.db")`，而 v1.x 后图服务改为通过 `runtime.state._get_graph_mgr()` 单例管理。`web/api.py` 未随架构迁移更新，仍试图自举旧模块，导致生产环境 graph 能力被禁用。
- **需进一步验证**:
  1. `runtime_graph` 模块在何时被移除？
  2. `graph/compat.py` 与 `runtime.graph.GraphManagerCompat` 的语义是否一致？
  3. 是否存在其他文件仍引用 `runtime_graph`/`store` 旧路径？

### 主题 2：静默失败文化 vs 可观测性约定
- **代表问题**: L5-11, L5-12, L5-13
- **根因假设**: 代码在多处把“best-effort”等同于“失败时不出声”。这与项目 `CLAUDE.md` 中“降级功能用 `logger.warning`”的约定冲突。长期会导致线上问题难以定位。
- **需进一步验证**:
  1. 全仓库有多少 `except Exception:` 后使用 `logger.debug`？
  2. 哪些 silent catch 真正属于可忽略路径，哪些属于数据持久化/核心功能路径？

### 主题 3：scope filter 语义在端到端链路中的泄漏
- **代表问题**: L2-4, L3-7, L4-9
- **根因假设**: scope 在 v1.6 作为“租户隔离”追加到存储层，但在 search rerank、curator、dashboard stats 等路径中，scope 与“全局聚合”的边界未统一。部分路径用 `{}` 表示 global-only，部分路径用 `None` 表示无过滤，存在歧义。
- **需进一步验证**:
  1. `None` vs `{}` vs `{user_id: None}` 在每一层的语义是否一致？
  2. `admin_global` 这个 curator 专用标记是否应下沉为 scope 模型的一部分？

### 主题 4：graph/store 耦合与 typed fact sidecar 的可达性
- **代表问题**: L6-14
- **根因假设**: typed fact sidecar 需要 graph 能力，但实现直接读取 `mem_store._graph`，没有通过公共接口。这导致测试和脚本化使用无法触发 sidecar，也可能在 runtime 初始化顺序变化时失效。
- **需进一步验证**:
  1. `_get_graph_mgr()` 与 `MemoryStore._graph` 的绑定关系是什么？
  2. 是否有其他模块重复了这种“直接读 `_graph`”的耦合？

## 建议的根本修正方向（待第二轮验证）

1. **统一 dashboard 的 graph 服务接入**: 让 `web/api.py` 通过 `runtime.graph.get_graph_manager_compat()` 或 `_get_graph_mgr()` 获取 graph 服务，而不是尝试自举旧模块。同时补充包模式集成测试。
2. **建立错误分级日志约定**: 对数据持久化、核心 reflection、graph sidecar 的失败路径统一使用 `logger.warning(..., exc_info=True)`；仅对资源清理等可忽略路径保留 debug。响应中增加 `degraded` 字段。
3. **澄清 scope filter 语义**: 在 `core/scope.py` 中显式定义 `None`（无过滤）、`{}`（global-only，IS NULL）、`{user_id: ...}`（租户过滤）三种形态，并在 search/curator/dashboard 中统一使用。
4. **解耦 graph 能力获取**: 为 `_record_typed_fact_sidecar` 提供 `_graph_for_store(store)` 辅助函数，优先 `store._graph`，回退到 `_get_graph_mgr()`，并在失败时 warning。
5. **补齐 weighted fusion 的 recency/effectiveness 项**: 与文档 `docs/ARCHITECTURE.md` 中“三层检索”描述对齐，确保两种 fusion 模式的 rerank 信号一致。

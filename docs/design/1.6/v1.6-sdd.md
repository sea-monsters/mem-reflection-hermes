# v1.6 软件开发设计文档 (SDD)

**版本**: v1.6
**日期**: 2026-06-11
**基线**: mem-reflection-hermes v1.5 (511 tests passed, runtime/schema 漂移已修复)
**方法论**: SDD → Test (RED) → Code (GREEN) → Freeze

---

## 1. 目的 (Purpose)

在 v1.5 模块重构和策展流水线完成后，v1.6 聚焦于两项运营级基础设施增强：

1. **Memory Event Ledger** — 为记忆生命周期操作（add/update/delete/supersede）建立 durable 事件账本
2. **Scoped Filters** — 引入 `user_id`/`agent_id`/`run_id` 作用域过滤，支撑 multi-agent 和 hosted 部署

这两项功能均基于现有 SQLite 架构，无外部依赖，且为后续高级功能（审计 UI、导出、context offload）奠定基础。

## 2. 问题定义 (Problem)

### 2.1 Event Ledger 缺失

当前 `MemoryStore.update()` 原地修改文件，无变更历史。`supersedes` 仅在前端可见，无法回答：
- "这条记忆上次修改是什么时候？"
- "谁（哪个 session/actor）修改了它？"
- "修改前后的内容差异是什么？"

参考: mem0 的 `history` 表记录每次 ADD/UPDATE/DELETE 的 before/after、actor、role。

### 2.2 作用域隔离不足

当前 `scope=user|project` 加上 `zone` 不足以支撑：
- 同一项目内多 agent 实例隔离
- 同一 agent 多 run/session 隔离
- Hosted service 多租户场景

参考: mem0 的 `user_id`/`agent_id`/`run_id` 作为 required tenancy scopes。

## 3. 设计目标 (Design Goals)

| 目标 | 描述 |
|---|---|
| **可追溯性** | 每条记忆的生命周期事件可被查询、回放 |
| **多租户隔离** | 同一 store 可安全承载多 user/agent/run 的记忆 |
| **向后兼容** | 无作用域时行为与 v1.5 完全一致 |
| **零外部依赖** | 继续使用 SQLite，不引入 Qdrant/Chroma/Redis 等 |
| **可测试性** | 所有行为可通过单元测试验证，边界条件全覆盖 |

## 4. 非目标 (Non-Goals)

| 非目标 | 原因 |
|---|---|
| Pluggable vector store | 需要真实 remote backend 需求才值得投入 |
| Typed temporal fact graph | 属于独立架构轨道，应单独设计 (W4) |
| Context offload / Mermaid refs | 引入新 storage 子系统，延后到后续 sprint (W3) |
| Import/export competing-tool paths | 运营功能，不影响核心记忆能力 |
| Distributed/multi-node store | 超出单机插件范围 |

## 5. 设计方案 (Proposed Design)

### 5.1 Wave 1: Memory Event Ledger

#### 5.1.1 数据模型

新增 `memory_events` SQLite 表：

```sql
CREATE TABLE memory_events (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    memory_id TEXT NOT NULL,
    event_type TEXT NOT NULL CHECK(event_type IN ('ADD','UPDATE','DELETE','SUPERSEDE','PIN','UNPIN')),
    old_body TEXT,
    new_body TEXT,
    old_frontmatter TEXT,  -- JSON serialized
    new_frontmatter TEXT,  -- JSON serialized
    session_id TEXT,
    actor_id TEXT,         -- 'user', 'agent', tool name, or subagent id
    created_at TEXT NOT NULL,  -- ISO 8601 UTC
    FOREIGN KEY (memory_id) REFERENCES memories(id)
);

CREATE INDEX idx_memory_events_memory_id ON memory_events(memory_id);
CREATE INDEX idx_memory_events_session_id ON memory_events(session_id);
CREATE INDEX idx_memory_events_created_at ON memory_events(created_at);
```

#### 5.1.2 API 扩展

**`MemoryStore` 方法**:
- `_record_memory_event(memory_id, event_type, old_body, new_body, old_fm, new_fm, session_id, actor_id)` — 私有记录方法
- `get_memory_events(memory_id, event_types=None, limit=None, after=None)` — 查询事件
- `get_memory_history(memory_id, max_depth=10)` — 返回事件链（替代现有 `srh_memory_history` 仅 supersedes 链）

**Schema 扩展** (`runtime/schemas.py`):
- `srh_memory_history` 新增参数: `include_events` (bool), `event_types` (array), `session_id` (string)

**Tool handler 更新** (`runtime/tools.py`):
- `_tool_srh_memory_write` — add/update/supersede 时记录事件
- `_tool_srh_memory_delete` — delete 时记录事件
- `_tool_srh_memory_history` — 扩展为返回事件链 + supersedes 链

#### 5.1.3 事件触发点

| 操作 | event_type | old_body | new_body | 触发位置 |
|---|---|---|---|---|
| 写入新记忆 | ADD | None | body | `srh_memory_write` |
| 更新现有记忆 | UPDATE | old | new | `MemoryStore.update()` |
| 标记替换 | SUPERSEDE | old | new | `srh_memory_write` (supersedes 时) |
| 删除记忆 | DELETE | old | None | `srh_memory_delete` |
| 固定/取消固定 | PIN/UNPIN | None | None | `MemoryStore.set_pinned()` |

#### 5.1.4 边界情况

- `old_frontmatter`/`new_frontmatter` 过大时截断存储（保留关键字段: id, created, source, confidence, pinned, tags, zone, supersedes）
- 删除记忆后，events 表保留（软关联），`get_memory_events` 仍可通过 memory_id 查询
- Session ID 未知时，使用空字符串而非 null
- Actor ID 默认从 hook 上下文获取，fallback 为 `"agent"`

### 5.2 Wave 2: Scoped Filters

#### 5.2.1 数据模型

扩展 `MemoryFrontmatter` 和 SQLite `memories` 表：

```sql
ALTER TABLE memories ADD COLUMN user_id TEXT;
ALTER TABLE memories ADD COLUMN agent_id TEXT;
ALTER TABLE memories ADD COLUMN run_id TEXT;

CREATE INDEX idx_memories_user_id ON memories(user_id);
CREATE INDEX idx_memories_agent_id ON memories(agent_id);
CREATE INDEX idx_memories_run_id ON memories(run_id);
CREATE INDEX idx_memories_scoped ON memories(user_id, agent_id, run_id);
```

Frontmatter YAML 新增可选字段:
```yaml
user_id: "user-abc"
agent_id: "agent-hermes-main"
run_id: "run-2026-06-11-001"
```

#### 5.2.2 API 扩展

**`MemoryStore` 方法**:
- `search(query, k=5, zone=None, filters=None)` — filters dict 包含 `user_id`, `agent_id`, `run_id`
- `list_memories(filters=None, limit=None)` — 带作用域过滤的列表
- `delete_by_filters(filters)` — 批量删除（curator 用）

**`SearchIndex.search()` 更新**:
- 在 scoring 前应用 filters: `WHERE (user_id IS NULL OR user_id = ?) AND ...`
- NULL 字段匹配所有（向后兼容）

**Schema 扩展**:
- `srh_memory_write` 新增可选参数: `user_id`, `agent_id`, `run_id`
- `srh_memory_search` 新增可选参数: `filters` (object with user_id/agent_id/run_id)
- `srh_memory_delete` 新增可选参数: `filters` (支持批量删除)

#### 5.2.3 过滤语义

| filter 字段 | 匹配规则 |
|---|---|
| `user_id` | 精确匹配；记忆无此字段时对所有请求可见（NULL = public） |
| `agent_id` | 精确匹配；同上 |
| `run_id` | 精确匹配；同上 |
| 组合 | AND 逻辑；`{"user_id": "u1", "agent_id": "a1"}` 仅匹配两者都满足 |

#### 5.2.4 边界情况

- 无 filters 时，行为与 v1.5 完全一致（检索所有记忆）
- 写入时若提供部分 filters，缺失字段存储为 NULL
- 更新时不可修改 scope 字段（防止 tenant escape）
- Curator 操作默认继承 store 的默认 filters

### 5.3 模块依赖图

```
core/store.py          ← memory_events table + scoped columns
core/models.py         ← MemoryFrontmatter + user_id/agent_id/run_id
core/search.py         ← SearchIndex.search(filters=...) applied before scoring
runtime/schemas.py     ← extended tool schemas
runtime/tools.py       ← event recording + filter passthrough
runtime/hooks.py       ← session_id / actor_id 注入
```

无循环依赖。所有变更在现有 layer 边界内完成。

## 7. 验收准则 (Acceptance Criteria)

### AC1: Event Ledger 功能

- [ ] `srh_memory_write` 写入新记忆后，`get_memory_events(id)` 返回一个 `ADD` 事件
- [ ] `srh_memory_write` 更新现有记忆后，返回 `UPDATE` 事件，包含 old/new body
- [ ] `srh_memory_write` 标记 supersedes 后，返回 `SUPERSEDE` 事件
- [ ] `srh_memory_delete` 删除记忆后，返回 `DELETE` 事件
- [ ] 事件查询支持按 `event_types`, `session_id`, `after` 过滤
- [ ] `srh_memory_history` 支持 `include_events=true` 返回事件链
- [ ] 事件表在 SQLite WAL 模式下并发安全

### AC2: Scoped Filters 功能

- [ ] `srh_memory_write` 支持 `user_id`/`agent_id`/`run_id` 参数

## 8. 风险评估

| 风险 | 概率 | 影响 | 缓解措施 |
|---|---|---|---|
| SQLite schema migration 失败 | 低 | 高 | 使用 `ALTER TABLE ADD COLUMN`（SQLite 原生支持）；添加版本检测和 graceful fallback |
| Event 记录影响写入性能 | 中 | 中 | 事件写入与文件写入在同事务内；benchmark 验证 <5% 延迟增加 |
| Scoped filters 破坏现有搜索排序 | 低 | 高 | filter 在 scoring 前应用，不改变排序逻辑；完整回归测试 |
| Frontmatter YAML 向后兼容 | 低 | 中 | 新增字段为 optional；parser 忽略未知字段并 warn |

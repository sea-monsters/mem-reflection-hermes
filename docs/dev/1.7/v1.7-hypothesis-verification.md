# v1.7 假设验证报告

**日期**: 2026-06-13  
**范围**: mem-reflection-hermes v1.7（runtime 注册、仪表盘、graph 绑定、typed fact sidecar、scope filter）  
**方法**: 在手动加载的包模式下执行最小复现脚本  

---

## 已验证假设

### H1. `runtime/registration.py` 未调用 `MemoryStore.set_graph()`

**验证方式**:
```python
from mem_reflection_hermes.runtime.registration import register
import inspect
src = inspect.getsource(register)
print('set_graph called:', 'set_graph' in src)  # False
```

**结论**: `register()` 仅在 `_post_delete_callbacks` 中注册了删除回调，没有将 graph manager 绑定到 store。这导致 `MemoryStore._graph` 和 `SearchIndex._graph` 在 runtime 初始化后始终为 `None`。

**影响**:
- `SearchIndex._search_impl()` 中的 Hebbian boost 分支被跳过（`self._graph is None`）。
- `_record_typed_fact_sidecar()` 读取 `mem_store._graph` 时返回，typed fact sidecar 不写入。
- `core/store.py:1100` 创建 SearchIndex 时传入的 `graph=self._graph` 为 `None`。

---

### H2. `SearchIndex._graph` 在 runtime 初始化后为 `None`

**验证方式**:
```python
from mem_reflection_hermes.runtime.state import _get_mem_store, _get_graph_mgr
ms = _get_mem_store()  # TypeError: MemoryStore.__init__() missing 1 required positional argument: 'user_root'
```

**进一步验证**（绕过有缺陷的单例 getter，手动创建 store）:
```python
from mem_reflection_hermes.core.store import MemoryStore
from mem_reflection_hermes.core.graph import GraphIndex
ms = MemoryStore(user_root=root, db_path=tmp/'memories.db')
graph = GraphIndex(tmp/'graph.db')
print('initial _graph:', ms._graph)  # None
ms.set_graph(graph)
print('after set_graph:', ms._graph is ms._get_search_index()._graph)  # True
```

**结论**: store 初始 `_graph=None`，只有显式调用 `set_graph()` 才能启用 graph 能力。runtime 注册流程缺少这步。

---

### H3. `web/api.py:_get_graph_interface()` 在包模式下返回 `None`

**验证方式**（模拟 `test_dashboard.py` 的 importlib 加载路径）:
```python
import importlib.util
spec_api = importlib.util.spec_from_file_location('dashboard_api', 'web/api.py')
mod = importlib.util.module_from_spec(spec_api)
import mem_reflection_hermes as srh
spec_api.loader.exec_module(mod)
print(mod._get_graph_interface())
```

**实际输出**:
```
Graph init (runtime_graph) failed
ImportError: attempted relative import with no known parent package
ModuleNotFoundError: No module named 'mem_reflection_hermes.runtime_graph'
_get_graph_interface(): None
```

**结论**: `web/api.py` 引用的 `..runtime_graph` 和 `mem_reflection_hermes.runtime_graph` 在 v1.7 已不存在。`graph/compat.py` 的模块名是 `mem_reflection_hermes.graph`，不是 `runtime_graph`。仪表盘在生产环境中无法获得真实 graph manager。

---

### H4. Typed fact sidecar 依赖 `store._graph` 绑定

**验证方式**:
```python
from mem_reflection_hermes.reflection.runtime import _record_typed_fact_sidecar
_record_typed_fact_sidecar(ms, fm, body)  # without graph binding
print('facts without graph:', len(graph.typed_facts(source_memory_id='mem-1')))  # 0
ms.set_graph(graph)
_record_typed_fact_sidecar(ms, fm, body + ' v2')  # with graph binding
print('facts with graph:', len(graph.typed_facts(source_memory_id='mem-1')))  # 1
```

**结论**: 未绑定 graph 时，typed fact sidecar 完全不工作；绑定后正常工作。结合 H1/H2，v1.7 的 typed fact sidecar 在 production Hermes 中实际上被静默禁用。

---

### H5. Scope filter 的 `None` / `{}` / `{field: None}` 语义不一致

**验证方式**:
```python
from mem_reflection_hermes.core.scope import normalize_scope_filters, build_scope_clauses, scope_from_values

normalize_scope_filters(None)              # -> None
normalize_scope_filters({})                # -> {}
normalize_scope_filters({'user_id': None}) # -> {'user_id': None}
scope_from_values(user_id=None)            # -> {}
build_scope_clauses({})                    # -> ([], [])
build_scope_clauses({'user_id': None})     # -> (['user_id IS NULL'], [])
build_scope_clauses({'user_id': 'u1'})     # -> (['user_id = ?'], ['u1'])
```

**结论**:
- `None` 表示“无过滤”。
- `{}` 在 `build_scope_clauses` 中表示“无过滤”（返回空 clauses），但在语义上容易被误解为“global-only”。
- `{field: None}` 表示“global-only”（生成 `IS NULL`）。
- `scope_from_values(user_id=None)` 过滤掉 None 值，返回 `{}`，因此无法表达“我要查 user_id IS NULL 的全局记忆”。

这种歧义会导致 API 调用方在传入 `{}` 时期望“仅全局”，但实际得到的是“全部”。

---

## 根本原因总结

1. **Graph 生命周期未在注册时完成 wiring**: `runtime/registration.py` 缺少 `ms.set_graph(gm)`。
2. **Dashboard 未完成包重构迁移**: `web/api.py` 仍引用已删除的 `runtime_graph` 模块。
3. **Scope filter 缺少统一语义模型**: `None`/`{}`/`{field: None}` 被不同模块解释。
4. **静默失败掩盖了上述问题**: 由于核心路径使用 `logger.debug` 或直接吞异常，生产环境中 graph 能力完全失效却没有明显告警。

---

## 修复计划

### P0（阻塞性）

1. **runtime/registration.py**: 在 register() 中 `_get_mem_store()` 和 `_get_graph_mgr()` 之后调用 `ms.set_graph(gm)`。
2. **web/api.py**: 将 `_get_graph_interface()` 改为通过 `runtime.graph.get_graph_manager_compat` 解析。

### P1（高影响）

3. **全库日志分级**: 把数据持久化/核心 reflection/graph/bridge 路径的 `logger.debug` 提升为 `logger.warning(..., exc_info=True)`。
4. **仪表盘降级标记**: 在 dashboard 响应中增加 `degraded: True` 或 `partial: True`，让前端/调用方知道哪些子系统不可用。

### P2（中影响）

5. **core/scope.py**: 明确 `None`/`{}`/`{field: None}` 语义，或引入 `ScopeIntent` 枚举。
6. **测试补充**: 添加包模式集成测试，验证 `_get_graph_interface()` 返回非 None、`set_graph()` 后 Hebbian boost 生效、typed fact sidecar 真实写入。
